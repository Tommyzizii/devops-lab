We ignore .terraform/ because it contains downloaded provider plugins that can be recreated.

We ignore *.tfstate because Terraform state files contain information about our infrastructure and may include sensitive data. They should not be committed to GitHub.

Phase 2

1.
Terraform state files should never be committed to a public repository because they may contain sensitive information such as infrastructure details, resource IDs, IP addresses, and even secrets. Exposing them can create serious security risks.

Phase 3

1. What does the -p 8080:80 flag do?

It maps port 8080 on the host machine to port 80 inside the Docker container, allowing the application to be accessed through http://localhost:8080.

2. Why do we push the image to Docker Hub before deploying to AWS?

Docker Hub acts as a central image registry. The EC2 instance can download the image directly from Docker Hub instead of requiring the image to be built on the server.

3. What is the difference between docker build and docker run?

docker build creates a Docker image from a Dockerfile. docker run starts a container from an existing Docker image.

Phase 4

1. What is the purpose of terraform plan before terraform apply?

terraform plan previews the changes that Terraform will make to your infrastructure without actually creating, modifying, or deleting any resources. It allows you to verify that the configuration is correct before applying it.

2. What does the user_data field do in an EC2 resource?

The user_data field contains a startup script that is automatically executed the first time an EC2 instance boots. It is commonly used to install software, configure the operating system, and deploy applications automatically.

3. Why do we use a data source for the AMI instead of hardcoding an AMI ID?

A Terraform data source retrieves existing information from AWS instead of creating new resources. Using a data source for the AMI ensures Terraform always selects the latest matching Amazon Linux image.
